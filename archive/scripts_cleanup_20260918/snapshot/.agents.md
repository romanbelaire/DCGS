# Repository Agent Instructions

## Slurm Batch Ownership

The user owns all Slurm execution. Agents must never submit, start, attach to,
restart, requeue, cancel, or otherwise mutate a Slurm job on the user's behalf.
This includes, but is not limited to:

- `sbatch <script>`
- `srun ...`
- `srun --jobid=<job-id> ...`
- `scancel ...`
- `scontrol update ...`
- `scontrol requeue ...`

When the user asks to run an experiment, prepare and validate the code and batch
script, then give the user the exact commands to execute manually. Do not run
the submission command, even when the request uses wording such as "start the
run", "launch the job", or "submit the batch". Wait for the user to provide the
job ID or resulting output before monitoring or diagnosing it.

Read-only scheduler inspection is allowed when relevant, including `squeue`,
`sacct`, `sinfo`, and `scontrol show`. Static validation such as `bash -n` and
`sbatch --test-only` is allowed, because it does not start a workload. Prefer to
give the validation command to the user unless they explicitly ask the agent to
perform validation.

## Manual SafeDialBench DCGS Smoke

From the repository root, the user can validate and submit the one-dialogue A40
smoke with:

```bash
cd /common/home/users/d/darrius.ng.2024/projects/RL-Defense/DCGS
bash -n scripts/slurm/run_safedial_dcgs_smoke.sbatch
sbatch --test-only scripts/slurm/run_safedial_dcgs_smoke.sbatch
sbatch scripts/slurm/run_safedial_dcgs_smoke.sbatch
```

The last command prints the real job ID. The user can inspect it with:

```bash
squeue -j <job-id> -o '%i|%j|%T|%M|%l|%b|%R'
sacct -j <job-id> --format=JobID,JobName,State,ExitCode,Elapsed,NodeList -n -P
tail -f outputs/slurm/safedial-dcgs-smoke-<job-id>.out
tail -f outputs/slurm/safedial-dcgs-smoke-<job-id>.err
```

Do not prepare or recommend submission of the full 2,037-dialogue DCGS run
until the smoke completes successfully and its output integrity, runtime, and
peak GPU memory have been checked. The full run must use a separate output
directory from both the baseline and smoke runs.

## Manual SafeDialBench Baseline Judging

Baseline judging is CPU-only but makes paid API requests. The full validated
baseline contains 2,037 dialogues requiring 10,029 turn judgments. The user can
validate and submit the resumable judge batch with:

```bash
cd /common/home/users/d/darrius.ng.2024/projects/RL-Defense/DCGS
bash -n scripts/slurm/run_safedial_baseline_judge_full.sbatch
sbatch --test-only scripts/slurm/run_safedial_baseline_judge_full.sbatch
sbatch scripts/slurm/run_safedial_baseline_judge_full.sbatch
```

Agents must not execute the final submission command. The judge writes each
successful call immediately; rerunning the identical batch resumes missing or
failed calls. A result is final only when
`outputs/safedial_baseline/zephyr_7b_beta_full/judgments_gpt-4o-mini/aggregate.json`
contains `"complete": true`.
